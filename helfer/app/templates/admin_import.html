Warum beide Dateien zusammen

In beiden Dateien ist eine Zeile ein Platz, nicht eine Schicht. Der Bedarf einer Schicht ist die Summe aus offenen und vergebenen Zeilen.

Eine voll besetzte Schicht steht deshalb nur in Vergebene Posten, eine ganz leere nur in Offene Posten. Erst beide zusammen ergeben den richtigen Bedarf.

Der Import lässt sich beliebig wiederholen: er rechnet den Bedarf jedes Mal neu aus und ersetzt alle Einteilungen, die aus einem früheren Import stammen. Was hier von Hand eingetragen wurde, bleibt unangetastet – ebenso Schichten, die in den Dateien nicht mehr vorkommen.

Direkt von der Helferliste holen

{% if abruf_moeglich %}

Holt beide Listen selbst beim Dienst – kein Herunterladen und Hochladen. Danach passiert genau dasselbe wie bei hochgeladenen Dateien: derselbe Bedarf, derselbe Bericht, dieselbe Wiederholbarkeit.

Kann einen Moment dauern – es sind drei Aufrufe beim Dienst: anmelden, vergebene Posten, offene Posten.

{% if uhr_steht %}

Von selbst läuft gerade nichts: JETZT_FEST steht in der Konfiguration, die Uhr also still. Jeder Lauf trüge denselben Zeitstempel, und eine Vorführung soll keine fremden Server abfragen. Der Knopf hier geht.

{% elif abruf_takt > 0 %}

Läuft auch von selbst, alle {{ abruf_takt }} Minuten. Ein selbsttätiger Lauf übernimmt allerdings nichts, was nach einem Ausfall aussieht – etwa eine Ausfuhr, die auf einmal halb so viele Zeilen hat. Der Knopf hier fragt nicht nach.

{% endif %} {% else %}

Dafür fehlen die drei Adressen in der Konfiguration: IMPORT_LOGIN_URL, IMPORT_URL_VERGEBEN und IMPORT_URL_OFFEN. Sie enthalten persönliche Zugangstoken und gehören ausschließlich in die .env auf dem Server – wer den Login-Link hat, sieht die ganze Helferliste samt Adressen und Telefonnummern. Solange sie fehlen, geht der Weg über die Dateien.
